# 작전 등록 및 관리

`/admin/operations`에서는 실제 Discord로 로그인한 OFFICER 또는 ADMIN이 작전을 등록하고 수정합니다. 관리자 화면의 권한 검사 외에 서버 데이터 계층이 현재 로그인 사용자와 저장된 권한, Discord 계정 연결을 다시 확인합니다. Mock 계정으로 실제 데이터를 읽거나 변경할 수 없습니다.

새 작전은 현재보다 미래의 시작 시각을 갖는 예정 상태로 등록합니다. 제목, 종류, 안내, 시작·종료 시각, 정원, 연결할 시즌을 입력합니다. 시즌 없이 등록할 수도 있습니다. 연결할 시즌은 예정 또는 진행 중이어야 하며, 작전 일정은 시즌 시작부터 정산 시각 사이에 들어가야 합니다. 시작 전에는 완료 처리할 수 없습니다.

수정 요청은 화면에 표시된 최신 저장 시각을 포함합니다. 다른 관리자가 먼저 수정한 경우 기존 화면의 저장을 거절하고 새로고침을 안내합니다. 참가 응답이 하나라도 있으면 시즌을 옮길 수 없고, 정원은 저장된 참가 확정 인원 이상이어야 합니다. 탈퇴한 계정의 참가 이력도 이 정원 판단에 포함됩니다. 기존 역할과 역할 정원, 참가 응답은 작전 편집으로 교체되지 않습니다.

시작된 작전을 완료 또는 취소 처리할 때는 기존 시작 시각을 유지할 수 있습니다. 과거 시각으로 시작 일정을 변경할 수는 없습니다. 완료·취소된 작전과 정산·보관 시즌의 작전은 읽기 전용이며 다시 예정 상태로 되돌리지 않습니다. 기록을 삭제하는 기능은 제공하지 않습니다.

작전 목록과 상세 정보는 선택한 공개 필드만 반환합니다. 참가자 정보에는 표시 이름, 공개 프로필 주소, 응답 상태와 역할 이름만 사용합니다. 게임 UID와 Discord 토큰은 읽지 않거나 브라우저로 전달하지 않습니다. 모든 날짜는 ISO 문자열입니다.

승인된 멤버는 `/ops`에서 모든 예정 작전과 완료·취소 기록을 확인하고, `/ops/[id]`에서 브리핑과 참가 응답을 사용할 수 있습니다. 참가 명단에는 현재 승인된 멤버의 공개 정보만 표시합니다. 보존된 이전 응답은 정원과 응답 수에 계속 포함됩니다. 참가 버튼은 기존 시즌 참가·진행 단계·시작 시각·작전 및 배정 역할 정원 정책을 적용하고, 실제 저장 시에도 같은 정책을 다시 검사합니다. 공개 방문자와 Mock 계정에는 미리보기 안내를 표시하고 실제 작전 정보를 읽지 않습니다.

변경은 권한 공통 잠금, 현재 사용자, 연결된 시즌, 작전 순서로 잠근 PostgreSQL 트랜잭션에서 처리합니다. 일정과 정원 검증, 저장, 공개 식별자 및 상태만 담은 감사 로그가 함께 완료됩니다. 시즌 관리 및 참가 응답 저장도 같은 잠금 순서를 사용해 동시 변경에 대비합니다.

서버 계약은 `getOperationAdminData()`, `getOperationAdminDetail(id)`, `mutateOperationAdministration(input)`입니다. 변경 입력은 엄격한 `SAVE_OPERATION` 형식이며, 클라이언트가 사용자 ID나 권한을 지정할 수 없습니다. 작업 완료 응답에는 저장된 작전 ID만 반환합니다.
