# 멤버 정보와 관리자 권한

전체 멤버 목록, 멤버 프로필 조회, 가입 승인·보류·재검토·승인 취소·역할 변경은 `ADMIN` 전용입니다. 메뉴를 감추는 것과 별도로 직접 URL, Server Action, 서버 데이터 함수에서 같은 권한을 확인합니다.

## 권한 구분

| 기능                                | APPLICANT | MEMBER | OFFICER | ADMIN |
| ----------------------------------- | --------- | ------ | ------- | ----- |
| 본인 프로필 등록·수정               | 가능      | 가능   | 가능    | 가능  |
| 다른 사람의 프로필 조회·수정        | 불가      | 불가   | 불가    | 가능  |
| 전체 멤버 메뉴·목록·프로필          | 불가      | 불가   | 불가    | 가능  |
| 가입 승인·보류·재검토·역할 관리     | 불가      | 불가   | 불가    | 가능  |
| 시즌·파티의 허용된 참가자 이름 확인 | 승인 후   | 가능   | 가능    | 가능  |

비로그인·가입 보류(`GUEST`) 계정은 본인 프로필 편집도 할 수 없습니다. 기존 시즌·파티 참가 자격, 작성자 관리, 운영진의 시즌·파티 관리 권한은 멤버 목록 권한과 구분합니다. 관리자가 시즌 미등록 상태에서 파티를 관리할 수 있어도 본인의 참석 응답에는 시즌 등록이 필요합니다.

`canViewAdminMemberDirectory`는 관리자 전용 목록·프로필·메뉴의 정책입니다. `canApproveMember`도 관리자만 허용합니다. 이름이 비슷한 기존 `canViewMemberDirectory`는 승인 멤버의 운영 기능 자격 확인에 사용되는 호환 함수입니다. **이 함수로 전체 멤버 정보 읽기를 승인하지 않습니다.** 일반 운영 기능을 막지 않도록 두 정책을 합치거나 기존 함수의 역할 범위를 바꾸지 않습니다.

## 화면과 데이터 경계

상단 메뉴, 모바일 추가 메뉴, 메뉴 검색, HOME의 전체 멤버 카드와 승인 관리 링크는 관리자에게만 표시합니다. `/members`, `/members/[handle]`, `/admin/members`와 관리 상세 경로는 비관리자에게 멤버 정보를 반환하지 않습니다.

본인 정보는 `/onboarding?edit=1`의 별도 경로에서 수정합니다. 프로필의 handle은 저장된 식별자이며 일반 회원에게 공개 프로필 주소로 안내하지 않습니다. 관리자용 목록 DTO에서도 게임 UID는 제외합니다. UID는 본인 또는 관리자의 전용 편집 폼에서만 읽습니다.

시즌·파티 참가자 이름, 작전 참가 응답, 글 작성자 이름처럼 협업에 필요한 맥락 정보는 유지합니다. 이를 전체 멤버 목록으로 확장하지 않으며 비관리자의 참가자 DTO에는 다른 멤버의 프로필 handle을 넣지 않습니다. 프로필 링크가 필요한 새 기능은 화면 조건과 서버 DTO 조건을 함께 적용해야 합니다.

시즌 관리 화면의 전체 승인 멤버 선택지는 관리자에게만 제공하고 관리자의 참가자 추가(`ENROL_MEMBERS`)도 같은 제한을 따릅니다. 운영진은 기존 시즌 참가자의 이름과 시즌 정보를 계속 확인할 수 있습니다. 참가자 추가 선택지를 숨기는 것으로 끝내지 않고 서버에서 현재 관리자 역할을 재확인합니다.

## 저장과 최신 역할 확인

`server/member-management.ts`의 관리자용 목록·관리 목록·대상 계정 조회는 권한 확인 후 트랜잭션에서 현재 DB 역할과 Discord 연결을 다시 읽습니다. 역할이 이미 `OFFICER`로 바뀐 계정이 이전 `ADMIN` 표시를 가지고 있어도 전체 멤버 정보를 읽을 수 없습니다.

관리자용 읽기는 공통 권한 advisory lock의 공유 잠금과 사용자 행의 공유 잠금을 사용합니다. 역할 변경은 같은 권한 잠금과 관련 사용자 행의 배타 잠금을 사용합니다. 역할·프로필 쓰기, 가입 승인과 감사 기록은 원자적으로 저장합니다. 브라우저가 보낸 역할·작성자 필드로 권한을 결정하지 않습니다.

`saveMemberProfile`은 본인 편집 또는 관리자 편집을 허용합니다. `/admin/members`의 프로필 변경 Action은 `saveManagedMemberProfile`을 사용하며 **본인의 프로필을 제출하더라도 관리자 권한을 추가로 요구**합니다. 자기 프로필 편집을 허용한다는 이유로 관리자 Action을 일반 회원에게 열지 않습니다.

관리자용 읽기·관리 거절은 로그아웃 처리가 아닙니다. 일반 멤버·운영진의 승인 상태와 허용된 시즌·파티·빌드 기능은 유지됩니다. `UNAVAILABLE`은 일시적인 연결 확인 실패로 구분하여 재시도를 안내하며, 실패를 데모 자료나 추정 관리자 권한으로 대체하지 않습니다. 실제 세션 만료와 확인된 서버 탈퇴는 기존 인증 정책을 따릅니다.

로그인한 운영진이 관리자 전용 섹션을 직접 열면 접근 가능한 관리 홈으로 이동하여 전용 권한 안내를 표시합니다. 일반 멤버의 관리 URL 접근은 HOME으로 돌아갑니다. 권한 부족을 이유로 유효한 계정을 로그인 화면으로 보내거나 재인증시키지 않습니다.

## 유지보수와 검증

정책 변경 시 중앙 역할 표, 직접 페이지, 직접 Server Action, 서버 데이터 읽기, 캐시된 관리자 표시와 실제 DB 역할의 불일치, Discord 연결 제거, 본인 프로필 편집을 함께 확인합니다. 문구나 메뉴 변경만으로 접근 제한을 구현하지 않습니다.

핵심 회귀 검증은 `packages/domain/tests/permissions.test.ts`, `member-policy.test.ts`, `member-page-authentication.test.ts`, `admin-authorization.test.ts`, `member-admin-access.integration.ts`에 있습니다. 실제 DB 검증은 로컬 대상 제한과 rollback fixture를 사용하며 실제 멤버 역할을 변경하지 않습니다. 시즌 전역 선택지의 운영진 차단, 기존 참가자 이름 유지, 오래된 관리자 주장에 대한 DB 재검사도 같은 통합 검증에 포함합니다.

최초 관리자 지정과 마지막 관리자 보호는 [가입 승인 문서](member-approval.md), 세션 표시·권한 검증의 구분은 [Discord 세션 정책](discord-session-policy.md), 시즌·파티 참가 경계는 [파티 모집 문서](party-recruitment.md)를 참고합니다.
