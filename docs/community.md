# 하이브 커뮤니티와 공지

승인된 Discord 멤버가 하이브 안에서 글·댓글·답글을 공유하는 기능입니다. 게시글은 서식과 사진 배치, YouTube 영상 참조를 지원하며 게시글·댓글·답글에 좋아요를 표시할 수 있습니다. 빌드 연결은 관리자에게 승인된 공유 버전을 사용합니다. 빈 목록을 자동으로 예시 글로 바꾸지 않습니다. 2026-10-08 사용자 요청에 따라 로컬 DB에 카테고리별 5개씩 총 25개의 `[예시]` 글을 추가했습니다. `apps/web/scripts/seed-sample-content.mjs`는 현재 로컬 DB에서만 실행되고 고정 ID로 재실행 중복을 방지합니다.

## 경로와 읽기 권한

| 경로                                 | 기능                                     |
| ------------------------------------ | ---------------------------------------- |
| `/community`                         | 자랑을 제외한 게시판·분류·검색·최근 공지 |
| `/community/showcase`                | 자랑하기 전용 사진 목록·검색·페이지 이동 |
| `/community/new`                     | 승인 회원의 글 작성                      |
| `/community/[id]`                    | 게시글·댓글·연결한 빌드 버전             |
| `/community/[id]/edit`               | 본인 글 수정                             |
| `/announcements/[id]`                | 승인 회원의 공지 읽기                    |
| `/admin/community`                   | 운영진의 숨김·보관된 글 검토와 공지 목록 |
| `/admin/community/notices/new`       | 운영진 공지 작성                         |
| `/admin/community/notices/[id]/edit` | 운영진 공지 수정                         |

실제 커뮤니티 글·댓글·공지 내용은 `MEMBER`, `OFFICER`, `ADMIN`에게만 제공합니다. 비로그인, 개발 계정, 신청·보류 계정은 실제 내용을 읽거나 변경하지 못합니다. 커뮤니티 게시글을 공개하는 별도 `PUBLIC` 모드는 없습니다.

읽기 Provider는 `LIVE`, `DEMO`, `PENDING`, `ERROR`, `REAUTH`, `LEFT`를 구분합니다. 일시적인 Discord 연결 오류를 로그아웃이나 데모 글로 바꾸지 않습니다. 편집·관리 읽기와 저장 함수는 안전한 `CommunityError` 코드와 메시지를 사용하며 DB 진단이나 저장된 비공개 정보를 응답에 넣지 않습니다.

## 작성자와 운영진의 권한

| 작업                | 승인 회원             | OFFICER / ADMIN           |
| ------------------- | --------------------- | ------------------------- |
| 글·댓글 작성        | 가능                  | 가능                      |
| 본문 수정           | 본인이 작성한 글·댓글 | 본인이 작성한 글·댓글     |
| 글·댓글 보관        | 본인 작성물           | 본인·다른 작성자의 작성물 |
| 글·댓글 숨김·표시   | 불가                  | 가능                      |
| 게시글 고정·해제    | 불가                  | 가능                      |
| 공지 작성·수정·보관 | 불가                  | 가능                      |

운영진의 관리 권한으로 다른 회원의 본문을 임의 수정하지 않습니다. 일반 회원이 운영진이 고정한 본인 글을 수정하면 기존 고정 상태를 보존합니다. 본문 수정은 숨김 상태를 자동 해제하지 않습니다.

공개 목록은 숨김·보관된 글과 현재 승인되지 않은 작성자의 글을 제외합니다. 숨김·보관된 글은 작성자와 운영진이 직접 상세에서 확인할 수 있으며, 보관된 글에는 새 댓글을 달 수 없습니다. 관리자는 보관된 행도 검토할 수 있지만 복원 기능은 이번 범위에 없습니다.

글·댓글 작성자 이름은 게시물 맥락에서 표시합니다. 전체 멤버 목록과 프로필은 관리자 전용이므로, 조회자의 현재 역할이 `ADMIN`일 때만 작성자의 프로필 handle을 DTO에 포함합니다. `MEMBER`와 `OFFICER`의 DTO에는 handle이 `null`입니다. UID·Discord 토큰·이메일·세션 정보는 커뮤니티 DTO에 포함하지 않습니다. 자세한 경계는 [멤버 정보 정책](member-privacy.md)을 참고합니다.

## 카테고리와 텍스트

카테고리는 공략(`GUIDE`), 팁(`TIP`), 질문(`QUESTION`), 빌드 공유(`BUILD`), 자랑(`SHOWCASE`), 자유게시(`GENERAL`)입니다. 공통 키·표기는 `apps/web/src/lib/community-policy.ts`에서 관리합니다. `0009_community_showcase.sql`은 기존 글을 유지하면서 DB 카테고리 검사에 자랑을 추가합니다.

커뮤니티 내부의 ‘게시판 / 자랑하기’ 전환으로 두 공간을 나눕니다. 헤더에는 커뮤니티 메뉴 하나를 유지하며 별도 사진 메뉴나 Hover 드롭다운을 추가하지 않습니다. 게시판(`/community`)의 전체·분류·검색·개수·페이지에서 자랑 글을 제외하고, 자랑하기(`/community/showcase`)는 자랑 글만 조회합니다. 일반 글쓰기의 분류에도 자랑을 표시하지 않으며 자랑 올리기는 전용 화면에서 시작합니다. 실제 홈과 데모 홈의 최근 글·갤러리 자동 노출도 자랑을 제외합니다. 통합 검색은 사용자가 직접 검색할 때 자랑 글을 찾을 수 있도록 유지하며 결과에 ‘자랑하기’를 표시합니다. 운영진의 관리 목록은 두 공간과 숨김 글을 함께 확인할 수 있는 기존 범위를 유지합니다.

자랑 목록은 기존 카드 디자인을 활용해 데스크톱 3열, 중간 화면 2열, 모바일 1열로 표시합니다. 본문의 첫 사진을 대표 사진으로 보여주고 사진이 여러 개면 고유 사진 수를 표시합니다. 사진은 비율을 보존하고 클릭하면 기존 상세 화면에서 전체 사진·설명·댓글을 볼 수 있습니다. 사진이 없는 자랑 글도 허용합니다. 목록 DTO는 사진 URL·설명·개수만 추가하며 이미지 원본 바이트를 조회하거나 본문 전체를 클라이언트로 전달하지 않습니다. 사진 요청은 기존 승인 회원 접근 검사를 그대로 사용하며 지연 로딩합니다.

글·댓글·답글·수정·보관 이동은 `section=SHOWCASE` 복귀 정보를 유지합니다. 알림과 북마크처럼 쿼리가 없는 상세 접근도 실제 저장된 분류를 기준으로 자랑하기 목록으로 돌아갑니다. 기존 `/community?category=SHOWCASE` 주소는 검색어와 페이지를 유지해 전용 목록으로 연결합니다. 글·사진·댓글·좋아요 데이터와 DB 구조는 분리 과정에서 변경하지 않습니다.

목록의 요약은 서식 문서의 실제 문단·제목에서 추출합니다. 이미지의 대체 문구·설명은 저장과 검색에 유지하되 목록 요약에 반복 표시하지 않으며, 사진만 있는 글은 요약 문단을 생략합니다. 문서가 없거나 손상된 기존 글은 저장된 본문을 요약으로 사용합니다. 작성자·날짜와 분류 배지를 두 열로 배치하고 좋아요·댓글 이동을 같은 높이의 반응 행으로 묶습니다. 자랑 목록의 제목은 두 줄까지만 보이고 상세에서는 전체를 표시합니다.

게시글 상세는 최대 1,000px의 읽기 영역 안에 제목·작성자·본문·반응을 배치합니다. 댓글 이동은 댓글 영역의 앵커를 사용하며 수정·보관·숨김·고정은 권한이 있는 회원의 ‘글 관리’ 메뉴에서 제공합니다. 댓글과 답글 작성·삭제·좋아요 권한은 기존과 동일합니다.

커뮤니티와 통합 검색은 제목·본문을 대상으로 유지하며 댓글·답글 검색은 포함하지 않습니다. 빌드 계산은 관리자들이 수식과 적용 조건을 정한 뒤 별도 구현합니다.

제목은 2~160자, 글·공지 본문은 1~20,000자, 댓글·답글은 1~4,000자입니다. 저장 경계는 필수값·길이·ID·업데이트 버전을 검사하고 예상하지 않은 작성자·숨김·보관 필드를 거절합니다. 게시글의 서식 문서는 허용한 노드만 저장하며 서버에서 계산한 일반 텍스트를 함께 보존해 검색에 사용합니다. 문서당 사진은 최대 10개이고 등록·저장 권한은 이미지 참조 연결과 같은 트랜잭션에서 확인합니다. 업로드 중이거나 실패한 사진이 있으면 게시글 저장을 차단합니다. 기존 문자열 본문도 그대로 읽을 수 있습니다. 입력 HTML을 실행하거나 `dangerouslySetInnerHTML`로 렌더링하지 않으며, 영상은 검증한 YouTube 주소만 참조합니다.

## 답글과 좋아요

답글은 최상위 댓글 아래 한 단계만 허용합니다. 부모 댓글은 같은 게시글에 속해야 하며, 신규 답글을 작성할 때 숨김·삭제되지 않은 승인 회원의 댓글인지 다시 확인합니다. 댓글을 작성자가 삭제하면 일반 회원에게 원문과 작성자를 제공하지 않고 삭제 안내와 기존 답글을 보여줍니다. 운영진이 부모 댓글을 숨기면 해당 답글 묶음도 일반 회원에게 표시하지 않습니다.

좋아요는 현재 공개되고 승인된 작성자의 게시글·댓글·답글에 승인된 실제 멤버가 표시합니다. 항목과 회원의 조합은 한 번만 저장하고, 요청에서 원하는 선택 상태를 명시하여 중복 요청에도 수가 늘지 않습니다. 다시 누르면 취소하며, 현재 승인된 회원의 반응만 집계합니다. 좋아요로 본문 수정 시각을 바꾸지 않으므로 기존 글 수정 충돌 검사에 영향을 주지 않습니다. 빌드 좋아요는 현재 승인된 공유 게시 상태에 같은 원칙을 적용합니다.

## 빌드의 특정 버전 연결

- 글 작성자는 본인 소유이며 현재 공유가 활성화된 빌드의 승인된 버전을 선택합니다. `BUILD` 카테고리에는 버전 선택이 필수이며 다른 카테고리에서는 선택 사항입니다. 검토 대기·반려 버전은 선택하거나 연결할 수 없습니다.
- `community_posts.build_version_id`는 `build_versions.id`를 참조합니다. 새 빌드 버전이 만들어져도 기존 글의 연결 대상은 바뀌지 않습니다.
- 상세 링크는 `/lab/b/[buildId]?version=N`입니다. 편집 기준용 `from` 파라미터를 상세 버전 링크로 사용하지 않습니다.
- 저장할 때 공유 상태·소유자·보관 여부를 잠긴 빌드 행으로 다시 확인합니다. 다른 사람의 버전이나 비공개·보관된 빌드는 연결할 수 없습니다. 커뮤니티 저장이 빌드의 공개 범위를 자동 변경하지 않습니다.
- 연결 후 새 버전이 승인되어도 기존의 승인된 고정 버전은 유지합니다. 연결된 제목과 공개 범위는 해당 버전의 승인 요청에서 읽고 새 비공개 초안의 제목을 노출하지 않습니다. 공유가 철회·보관되거나 작성자의 승인 상태가 해제되면 제목·버전 링크·스냅샷을 반환하지 않고 확인 불가 안내를 표시합니다. 빌드 버전 FK는 기록으로 유지합니다.
- 버전 선택지는 최대 100개입니다. 더 많은 버전이 있으면 제한 안내를 제공하며, 편집 중인 글에 이미 연결된 오래된 유효 버전은 100개 안에 포함시켜 보존합니다. 전체 빌드 구성 JSON을 선택지나 게시글 DTO로 내려보내지 않습니다.

## 공지와 알림

기존 `announcements` 행을 그대로 사용하고 `archived_at`만 추가했습니다. 운영진은 공지의 제목·본문·고정 여부·발행 시각을 저장합니다. 일반 회원에게는 보관되지 않았고 발행 시각이 현재 이전인 공지만 제공합니다.

발행일시는 선택 입력이며 화면에서는 한국 시간의 날짜·시간을 사용합니다. Server Action은 실제 달력 날짜와 시간을 엄격히 검사하고 UTC ISO 값으로 변환합니다. 새 공지에서 비우면 즉시 발행하고, 수정 화면에서 비우면 잠긴 기존 행의 발행일시를 유지합니다. 표시된 기존 시각을 바꾸지 않은 경우 원래 저장된 초·밀리초도 보존합니다. 미래 시각을 선택하면 그 시각부터 멤버에게 보입니다.

HOME 공지는 최대 5개, 커뮤니티 공지 요약은 최대 6개입니다. 헤더 알림은 계정 설정에 맞춰 공지·파티·투표·댓글 이벤트를 읽습니다. 답글은 게시글 작성자와 부모 댓글 작성자에게 기존 댓글 알림 설정으로 전달하며 같은 회원이면 한 번만 표시합니다. 본인이 작성한 답글과 숨김·보관·승인 해제된 내용은 알림에서 제외합니다. 알림을 누르면 해당 댓글 묶음과 답글 페이지를 찾아 이동합니다. 예약 공지와 보관 공지는 일반 회원의 목록·상세·알림에서 제외합니다.

관리 목록의 ‘발행 예약’ 배지는 발행일시와 `CommunityDirectoryData.asOf`의 서버 조회 시각을 비교합니다. 브라우저 시계로 예약 여부를 판단하지 않습니다. 공지 관리 조회 DTO에 별도 시각 필드는 추가하지 않았으며, 관리 페이지에서 공지 목록과 함께 읽은 커뮤니티 Provider의 `asOf`를 사용합니다.

## 저장·동시 변경·보관

`0004_hive_community.sql`은 `community_posts`, `community_comments`를 추가하고 공지에 보관 시각을 추가한 migration입니다. 후속 migration은 답글 관계, 좋아요, 본문 사진 참조와 빌드 공유 승인 구조를 추가합니다. 작성자·게시글·빌드 버전 FK는 `restrict`이며, 답글의 동일 게시글 관계와 깊이 한계도 DB에서 검사합니다.

서버는 세션에서 작성자를 결정하고, 저장 전 Discord 멤버 자격과 트랜잭션 안의 현재 DB 역할·Discord 계정 연결을 다시 확인합니다. 역할 변경과 공유하는 승인 advisory lock을 먼저 얻고 사용자 행을 읽기 잠금으로 보호합니다. 새 글·댓글·공지의 작성·업데이트 시각은 동일하게 저장해 생성 직후 수정 이력으로 표시하지 않습니다. 이후 수정은 해당 행을 잠근 뒤 서버가 발급한 `expectedUpdatedAt`을 비교합니다. 업데이트 버전은 이전 값보다 반드시 증가하며, 충돌하면 이전 입력을 덮어쓰지 않고 새로고침 안내를 반환합니다.

댓글 변경은 게시글을 먼저 잠근 뒤 댓글을 잠가, 글 보관·숨김과 댓글 작성이 엇갈리지 않게 합니다. 보관은 행을 물리 삭제하지 않고 `archived_at`을 저장합니다. 댓글 작성자는 보관된 부모 글에 있던 본인 댓글도 보관할 수 있습니다. 저장·숨김·고정·보관은 변경 내용과 감사 기록을 같은 트랜잭션에 저장합니다.

## 조회량과 검증

게시글과 최상위 댓글은 각각 한 페이지 20개입니다. 답글은 각 댓글 아래 10개씩 오래된 순서로 표시하고 별도 페이지를 제공합니다. 새 댓글은 첫 페이지, 새 답글은 부모 묶음의 마지막 답글 페이지로 이동합니다. 상세는 최대 20개 묶음과 각 묶음의 제한된 답글만 읽으며 전체 답글을 한 번에 내려보내지 않습니다. 운영진 공지 목록도 20개 단위로 이동합니다. 제목·본문 검색은 최대 120자로 제한하며 `%`, `_`, `\`를 SQL 검색 와일드카드로 해석하지 않습니다.

읽기는 승인 경계와 사용자 읽기 잠금을 유지한 `repeatable read` 트랜잭션을 사용해 목록과 전체 개수가 같은 시점을 가리키게 합니다. 글·댓글 목록은 해당 조회 범위만 읽으며 UID·토큰·전체 빌드 스냅샷을 미리 읽지 않습니다.

검증은 기존 커뮤니티 테스트와 `reaction-authorization.test.ts`, `reaction-actions.test.ts`, `like-button.test.ts`, `community-interactions.integration.ts`를 포함합니다. 실제 SQL 검사는 테스트용 행을 외부 트랜잭션에서 모두 롤백하며, 깊이·다른 글 부모 연결 차단·삭제/숨김 관계·페이지 한계·좋아요 중복 요청·현재 승인 범위·이미지 참조 소유·고정 승인 버전·알림 수신 범위를 확인합니다.
