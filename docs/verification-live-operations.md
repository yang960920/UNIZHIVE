# Discord 실제 연동 및 운영 데이터 검증

검증일: 2026-10-06. 사용자가 Discord 비밀키를 로컬 파일에 입력하고 다음 작업을 요청한 뒤 진행한 결과입니다.

## 완료한 실제 흐름

- Docker PostgreSQL 17.11: loopback `127.0.0.1:5433`, `uniz_hive`, 기존 18개 테이블 사용. 다른 프로젝트의 5432 서비스는 변경하지 않았습니다.
- Discord Client ID/Secret: 공식 OAuth client-credentials 교환으로 유효성을 확인하고 검증용 임시 토큰을 즉시 폐기했습니다. 값이나 응답 토큰을 출력하지 않았습니다.
- 사용자가 Chrome에서 직접 OAuth 승인과 게임 프로필 등록을 완료했습니다. 실제 OAuth callback, 가입 확인 API, 계정 연결과 프로필 저장이 정상 동작했습니다.
- 사용자가 지정한 Discord 사용자 ID를 대상으로 최초 관리자 CLI를 READY로 확인한 뒤 적용했습니다. CLI는 기존 로그인·프로필·암호화된 유효 토큰·현재 UNIZ 서버 가입을 다시 확인합니다. 역할은 Discord Role에서 자동 승격하지 않습니다.
- 실제 계정으로 HOME, SEASON, `/admin/members`에 접속해 DB 기록과 관리자 권한을 확인했습니다. 승인 멤버 1명·대기 신청 0명이며, 운영 시즌·작전·투표는 아직 등록 전입니다.
- 최종 빌드 후 개발 서버를 다시 시작하고 같은 실제 계정으로 `/admin/members`에 재접속했습니다. 관리자 권한과 저장된 프로필이 유지됐으며 추가 입력 없이 정상 화면을 확인했습니다.

기본 테스트에는 암호화/변조·잘못된 계정 바인딩·권한 정책·신청/프로필 검증·실제/데모 경계·인증 장애 상태·Discord 응답 및 갱신/탈퇴 판단이 포함됩니다. 동시 빌드가 생성 타입 파일을 갱신하는 동안 발생할 수 있는 검사 경합을 피하려고 빌드 완료 후 웹 타입 검사도 재실행해 통과했습니다.

인증 서명키는 사용 시점의 설정을 읽도록 보강했습니다. 같은 서버 렌더링 안의 중복 인증 조회만 공유하고, 다음 요청에서는 Discord 가입을 다시 확인합니다. 환경 갱신 후 서명키 선택과 독립 요청 검증도 기본 테스트에 포함됩니다.

PostgreSQL integration suite는 인증 주체와 외부 Discord 응답만 대체하고 실제 저장소·SQL·잠금·트랜잭션을 실행합니다. 다음을 확인했습니다.

1. 인증 장애·재로그인 필요·서버 탈퇴 상태는 데모 데이터로 바뀌지 않습니다.
2. 신청 승인과 감사 기록 저장, 공개 응답의 UID 제외.
3. Mock 쓰기, DB와 다른 오래된 관리자 주장, 대상 가입 확인 실패 거부.
4. 동시에 참가해도 정원 1명인 작전은 한 명만 GOING으로 저장.
5. 투표를 변경해도 동일 사용자/시즌에는 한 행만 존재하고 이동 준비 상태가 DB에 저장.
6. 마감된 투표, 다른 후보, 해제된 권한, Mock Provider 쓰기 거부.
7. 프로필 수정과 UID를 포함하지 않는 감사 메타데이터.
8. OAuth 토큰 암호문 저장과 정확한 계정 바인딩.
9. 확인된 탈퇴 시 GUEST·토큰 삭제·기록 보존 및 재가입 시 APPLICANT.
10. Discord 장애는 접근을 거부하면서 정상 역할을 거짓 탈퇴로 변경하지 않음.
11. 동시 인증 요청의 만료 토큰 갱신을 한 번만 실행.
12. 거부된 refresh token은 삭제하고 재로그인 요구.

Integration 검사는 로컬 `uniz_hive` DB만 허용하고 각 테스트가 생성한 UUID 데이터만 FK 순서대로 정리합니다. 기존 운영 데이터와 최초 관리자 기록을 삭제하지 않습니다. 기본 `pnpm test`는 DB 없이 실행 가능합니다.

## 화면 및 남은 범위

Chrome의 실제 로그인 상태에서 HOME/SEASON의 빈 상태와 멤버 승인 관리 화면을 확인했습니다. 브라우저 기본 데스크톱 너비에서 가로 넘침 없이 표시됐습니다. 결과 이미지는 Git에서 제외되는 `artifacts/live-admin-desktop.jpg`, `artifacts/live-home-desktop.jpg`입니다. 이번 Live 계정의 모바일 화면 검증은 별도입니다. 초기 Foundation의 모바일 데모 검증은 기존 기록을 참고합니다.

실제 사람 계정으로 서버를 탈퇴하거나 토큰을 고의 폐기하는 작업은 수행하지 않았습니다. 해당 실패 흐름은 검증된 외부 응답 분류·자동 테스트와 실제 DB 트랜잭션으로 확인했습니다. 권한 갱신은 다음 실제 요청에서 수행하며 별도 Discord Bot·배경 작업은 실행하지 않습니다.

시즌/작전 등록 CMS, Steam/공식 뉴스 집계, Discord 전체 온라인 현황, Community CRUD, Build Planner와 Simulator는 이번 작업에서 구현하지 않았습니다. 특히 현재 운영 기록이 비어 있는 것은 연결 실패가 아니라 등록 전 상태입니다.

## 후속 로그인 유지 수정 · 2026-10-06

실제 Discord 확인 중 간헐적인 HTTP 429와 261초 대기 응답을 확인했습니다. 기존 콜백은 이 일시 오류에서 세션의 사용자 표시를 제거하여 로그인 해제처럼 보이게 했습니다. JWT 자체는 유지되어 있었습니다. 로그인 표시와 실시간 가입·권한 검사를 분리하고, 보호된 읽기·쓰기는 가입 확인 실패 시 계속 차단하도록 수정했습니다.

- JWT와 쿠키의 만료를 7일로 맞추고 실제 로그인에서 세션 API를 15분마다, 화면 복귀 시 갱신합니다. 서버 로그에서 브라우저의 세션 API 200 응답을 확인했습니다. 네트워크 오류로 자동 로그아웃하지 않습니다.
- Discord 대기 시간은 안전한 숫자로 전달하고, 대기 중 반복 호출과 자동 미리 불러오기를 제한합니다. 가입 결과를 다음 요청에 재사용하지 않으며, 대기 종료 후 새 확인으로 탈퇴 여부를 판단합니다.
- 로그아웃 전에 갱신 요청을 취소하여 늦은 응답이 로그인을 복구하는 경합을 막습니다. 여러 활성 탭에는 신원 정보 없는 중단 신호만 전달합니다.
- 기존 실제 계정으로 Chrome과 앱 브라우저에서 로그인 표시가 유지되는 것을 확인했습니다. 앱 브라우저는 대기 종료 후 재로그인 없이 ADMIN 시즌 관리로 복구됐습니다. 시즌 상세와 관리 화면 왕복 및 새로고침도 통과했습니다.
- 프로필, 멤버, 시즌·작전 관리와 RSVP는 일시 오류에서 재시도를 안내하며 보호된 데이터 읽기와 쓰기를 실행하지 않습니다. 잘못된 기존 쿠키, 만료·취소된 동의, 확인된 서버 탈퇴는 기존 재인증·권한 규칙을 적용합니다.

7일 전체 경과는 실제 시간으로 기다리지 않았습니다. 갱신 주기·만료 설정·네트워크 실패·로그아웃 경합은 자동 검증으로 확인했습니다. 실제 사용자 계정의 로그아웃, 서버 탈퇴, 토큰 폐기와 기존 시즌 정보 변경은 수행하지 않았습니다. 확인 이미지는 `artifacts/session-kept-during-discord-delay.png`, `artifacts/session-restored-admin.png`입니다.

최종 소스의 `pnpm test`는 26개 파일·276개 테스트, `pnpm ops:verify`는 실제 PostgreSQL 7개 파일·44개 테스트가 통과했습니다. 전체 ESLint와 Production 빌드도 통과했습니다. 세션 갱신과 안전한 로그아웃 10개, 페이지·프로필 저장 복구 9개, 재시도 UI·관리 본문 차단 4개, 서버 쓰기 차단 2개의 회귀 검증을 포함합니다.

## 후속 기능 차단 수정 · 2026-10-06

사용자가 실제 시즌 버튼에서 권한 오류가 계속된다고 알려주었습니다. 앞선 수정은 로그인 표시와 쿠키를 유지했지만, 모든 보호 요청에서 Discord에 가입을 다시 확인하여 외부 호출 제한 중에는 승인된 사용자의 기능도 차단하는 문제가 남았습니다. 이전·다음 방향의 버전 검사나 시즌 승인 상태 변경이 원인은 아니었습니다.

보호 요청은 유효한 현재 계정·동의 범위·토큰 만료와 암호화된 인증 정보의 세대를 매번 확인하고, 성공한 Guild 가입 확인만 최대 5분 재사용합니다. DB 역할은 요청마다 그리고 저장 트랜잭션 안에서 다시 확인합니다. 멤버 승인 대상의 가입 확인은 계속 강제로 새 Discord 응답을 요구합니다. 재사용 기간은 접근하거나 오류가 발생해도 연장하지 않습니다. 만료·인증 정보 변경·삭제·확인된 탈퇴·권한 해제 흐름은 새 검증 및 기존 차단 규칙을 적용합니다. 자세한 경계는 [Discord 세션 정책](discord-session-policy.md)에 기록했습니다.

실제 앱 브라우저의 UNIZ 시즌에서 3→4→3 왕복을 빠르게 세 번 수행한 뒤 새로고침하고 한 번 더 왕복했습니다. 여덟 번의 단계 저장이 모두 성공했고 재로그인은 없었습니다. 마지막 단계는 원래의 3단계로 돌아왔으며 DB에서 APPROVED·ADMIN·기존 참가자 1명과 여덟 개의 저장 기록을 확인했습니다. 감사 기록은 유지했습니다. 시즌의 이름·일정·참가자는 변경하지 않았습니다.

최종 검증은 단위 테스트 28개 파일·297개와 실제 PostgreSQL 테스트 7개 파일·45개가 통과했습니다. 가입 증거의 기간·격리·폐기·동시 요청·늦은 로그인 확인 결과, 실제 이전·다음 입력 전달 및 저장 버전 충돌을 검사합니다. 확인 화면은 `artifacts/phase-controls-after-continuity-fix.png`입니다.
