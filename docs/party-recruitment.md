# 시즌별 파티 모집

`/ops`는 승인 멤버가 시즌을 선택하고 날짜별 파티를 확인하는 달력입니다. 날짜를 고르면 시작 시간 순으로 모집을 표시합니다. 파티 생성은 `/ops/new`, 상세는 `/ops/[id]`, 작성자·운영진 편집은 `/ops/[id]/edit`에서 처리합니다.

## 참가와 관리 권한

- 신규 파티는 승인된 `PLANNED` 또는 `ACTIVE` 시즌에 연결해야 합니다. 일반 멤버는 해당 시즌의 삭제되지 않은 참가 명단에 등록되어 있어야 생성할 수 있습니다.
- 일반 멤버는 현재 시즌 등록을 유지하는 동안 본인 모집을 수정·취소할 수 있습니다. 운영진·관리자는 열린 승인 시즌의 모집을 생성·관리할 수 있으며, 이 관리 권한에는 시즌 등록이 필요하지 않습니다.
- **참석 자격은 관리 권한과 별개입니다.** 운영진·관리자도 해당 시즌에 등록되어야 본인의 참석 응답을 저장할 수 있습니다.
- 파티가 먼저 만들어져도 이후 시즌에 등록한 승인 멤버가 참가할 수 있습니다. 참석 저장 시 현재 참가 명단을 다시 확인하며, 파티 생성 시 참가 명단을 고정하지 않습니다.
- 파티 생성은 작성자를 자동 참석 처리하지 않으며 시즌 가입도 하지 않습니다. 작성자도 상세 화면에서 참가를 선택합니다. 파티 참석·불참·취소는 시즌 등록을 변경하지 않습니다.
- 다른 사람의 참석 응답 변경·제외는 운영진·관리자만 가능합니다. 일반 작성자는 다른 참가자의 응답을 변경할 수 없습니다.

참석 응답은 `GOING`, `MAYBE`, `UNAVAILABLE`입니다. 신규 확정 참가 시 전체 정원과 기존 역할 배정의 정원을 함께 검사합니다. 예정 모집의 시작 시각 이후에는 참석 응답을 바꿀 수 없습니다. 역할·팀 배정을 새로 편집하는 기능은 이번 범위에 포함하지 않습니다.

## 콘텐츠와 시즌 조건

콘텐츠 목록과 안전한 작전 유형 매핑은 `apps/web/src/lib/party-content.ts`에서 관리합니다.

| 콘텐츠 키           | 표시      | 사용 조건                           | 저장 작전 유형 |
| ------------------- | --------- | ----------------------------------- | -------------- |
| `endless-deep`      | 무깊      | `endless-dream` 시나리오            | `RAID`         |
| `endless-kin`       | 무킨      | `endless-dream` 시나리오            | `RAID`         |
| `endless-shallow`   | 무얕      | `endless-dream` 시나리오            | `RAID`         |
| `gravity-condenser` | 응축기    | 시즌의 `gravityContentEnabled=true` | `RAID`         |
| `prime-war`         | 프라임 워 | 공통                                | `PRIME_WAR`    |
| `raid`              | 레이드    | 공통                                | `RAID`         |
| `farm`              | 파밍      | 공통                                | `FARM`         |
| `exploration`       | 탐험      | 공통                                | `EXPLORATION`  |
| `other`             | 기타      | 공통                                | `OTHER`        |

응축기 사용 가능 여부는 운영진이 시즌 정보에서 직접 설정합니다. 게임 서버에서 자동으로 감지하는 기능은 없습니다. 이전 저장 요청이 이 필드를 보내지 않으면 기존 값을 보존합니다.

생성·예정 상태 수정과 긍정 참석 응답(`GOING`, `MAYBE`)은 현재 시즌의 콘텐츠 조건을 다시 검사합니다. 생성 후 조건이 바뀌어 콘텐츠가 비활성화되면 새 참가·참가 확정은 거절합니다. 유효한 기존 참가자의 불참 처리, 운영진의 예약 제외, 기존 콘텐츠를 유지한 모집 취소는 가능합니다. 조회 화면도 참가·미정·취소 가능 여부를 각각 구분합니다.

## 저장 경계와 변경 충돌

기존 `operations`, `operation_participants`, `season_memberships` 테이블을 재사용합니다. 파티 이름, 콘텐츠, 장소·좌표 메모, 설명, 시작·선택 종료 시각, 정원과 상태를 저장합니다.

`server/party-administration.ts`의 공개 경계는 다음과 같습니다.

- `getPartyEditorData(id?)`: 현재 작성·관리 가능한 시즌과 편집 정보를 반환합니다.
- `saveParty(value)`: 신규 생성 또는 최신 버전을 확인한 수정·취소를 처리합니다.
- `managePartyParticipant(value)`: 운영진의 참가 응답 변경·제외를 처리합니다.

서버는 현재 인증·Discord 가입 상태와 승인 권한을 확인하고 저장 트랜잭션에서 DB 역할·Discord 연결·시즌 등록을 재검사합니다. 운영진이 다른 사람을 참가·미정 처리할 때도 대상의 서버 가입·승인·시즌 등록을 확인합니다. 공개 DTO에는 비공개 게임 UID나 OAuth 토큰을 포함하지 않습니다.

쓰기 잠금 순서는 공통 권한 advisory lock → 현재 사용자 → 시즌 → 작전입니다. 작전 잠금 아래에서 참석 인원과 역할 정원을 판단하고 사용자별 고유 참석 기록을 갱신합니다. 동일 파티의 중복 등록과 마지막 자리의 동시 신청을 이 경계에서 처리합니다.

모집 수정과 운영진의 명단 변경은 `expectedUpdatedAt`으로 최신 파티 버전을 제출해야 합니다. 파티 수정·신규 파티의 RSVP·명단 관리·시즌 제외에 따른 예약 해제는 파티 버전을 갱신합니다. 오래된 화면으로 저장하면 재확인을 요청합니다. 이미 참석 응답이 있는 모집의 연결 시즌을 바꿀 수 없으며, 정원을 확정 참가 인원보다 줄일 수 없습니다. 일정은 시즌의 시작·선택 정산 시각 범위 안이어야 합니다.

## 날짜와 조회 범위

입력·달력 날짜·시간 표시는 한국 시간(KST)으로 통일하고 DB에는 `timestamptz`로 저장합니다. 브라우저나 서버의 시스템 시간대에 따라 날짜가 바뀌지 않도록 날짜 경계와 그룹화를 계산합니다.

달력은 선택한 시즌의 표시 월 그리드 범위에서 날짜별 개수를 집계합니다. 목록은 선택한 날짜 또는 월 그리드 범위만 읽으며 시작 시각 순으로 최대 **페이지당 4개**를 반환합니다. 날짜별 모집 수는 페이지 이동과 관계없이 전체 개수를 표시합니다. 전체 개수와 다음 페이지를 별도로 제공하므로 그 이후 기록을 숨기거나 잘라내지 않습니다. 참석·역할 조회도 반환할 작전 범위로 제한합니다. 잘못된 월·날짜·시즌·페이지 입력은 기본값으로 처리하고 안내를 표시합니다.

이미 확정 참석한 다른 예정 파티와 일정이 겹치면 경고합니다. 겹침을 이유로 신청을 강제로 거절하지는 않습니다. 양쪽 종료 시각이 있으면 시간 구간을 비교하며, 종료 시각이 하나라도 없으면 **동일 시작 시각만** 비교합니다. 임의 소요 시간을 가정하지 않으므로 종료 미입력 일정의 모든 중복을 감지하는 기능은 아닙니다.

현재의 공통 권한 잠금은 서로 다른 파티 쓰기도 직렬화합니다. 유지보수 시 조회를 전체 기록으로 되돌리지 말고, 쓰기 처리량을 조정할 때에는 승인 취소·시즌 제외·정원 검사의 잠금 순서와 원자성을 함께 검토해야 합니다.

## 기록 보존과 기존 작전

운영진의 참가자 제외는 참석 기록을 삭제하지 않습니다. `UNAVAILABLE`로 전환하고 기존 역할 배정을 해제합니다. 관리자가 시즌 참가 명단에서 회원을 제외하면 그 시즌의 **미래 예정 작전** 예약을 해제하고 파티 버전·감사 기록을 갱신합니다. 시작된 작전과 과거 기록은 유지합니다. 모집 자체의 취소도 참석 이력을 삭제하지 않습니다.

기존 `contentKey=null` 작전과 `seasonId=null` 하이브 공통 작전은 보존합니다. 공통 작전은 달력에서 기존 일정으로 표시하며 기존 관리 경로를 사용합니다. 신규 파티에는 시즌이 필수이고, 새 편집 경계로 공통 작전을 변경할 수 없습니다.

`/admin/operations`의 기존 저장 함수는 신규 `contentKey` 파티의 변경을 거절하고 파티 편집 화면으로 안내합니다. 이를 통해 기존 작전 유형 선택으로 신규 콘텐츠 정보가 어긋나는 것을 막습니다. 기존 `contentKey=null` 작전은 기존 관리 기능과 시즌 진행 단계에 따른 RSVP 규칙을 유지합니다. 새로운 참가자 관리 UI는 지원하는 시즌 파티에만 표시합니다.

## 배포와 확인 항목

`0003_party_calendar.sql`은 아래 열만 추가하며 이전 기록을 다시 작성하지 않습니다. 이 migration은 로컬 PostgreSQL에 적용되었습니다. 다른 환경에서도 새 코드 사용 전에 적용해야 합니다.

- `operations.content_key`: nullable text
- `operations.meeting_point`: 기본값이 빈 문자열인 필수 text
- `seasons.gravity_content_enabled`: 기본값이 false인 필수 boolean

관련 회귀 검증은 `party-admin-policy.test.ts`, `party-season-policy.test.ts`, `party-calendar.test.ts`, `party-calendar-ui.test.ts`, `party-actions.test.ts`와 `party-administration.integration.ts`, `party-directory.integration.ts`, `party-season-reservations.integration.ts`에 있습니다. DB 검증은 로컬 대상 제한과 rollback fixture를 사용합니다. 실제 배포 검수에서는 신규 회원·기존 회원·운영진, 시즌 등록 전후, 자리 경쟁, 오래된 편집 화면, 비활성 콘텐츠의 예약 해제를 확인합니다.
