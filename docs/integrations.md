# Integration Foundation

All external services live behind adapters in `packages/integrations`. The public entry point exports contracts, explicitly labelled mocks and verified URL helpers. The `@uniz/integrations/server` entry point uses `server-only`; Discord tokens and future Steam secrets cannot be imported into client components.

## Discord — LIVE verified / local MOCK

Auth.js is used through stable `next-auth` v4 with App Router handlers and signed/encrypted JWT sessions. Live sign-in is enabled only when `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_GUILD_ID` and `DATABASE_URL` are configured. Production additionally needs `NEXTAUTH_SECRET` and an HTTPS `NEXTAUTH_URL`. Configure the Discord redirect URI as `<NEXTAUTH_URL>/api/auth/callback/discord`.

OAuth requests `identify guilds.members.read`. After identity confirmation, the server checks [Get Current User Guild Member](https://docs.discord.com/developers/resources/user#get-current-user-guild-member) against the configured UNIZ guild. The Discord identity is linked to a database user/account. A new user receives APPLICANT, then submits a Zod-validated game profile. Authorized officers/admins review, approve, hold or reopen applications and undo approvals; admin-only role changes cannot edit one's own authority or remove the final admin through management. Actual local OAuth consent, guild membership, profile registration and explicit first-admin bootstrap were exercised successfully on 2026-10-06.

Discord access/refresh tokens are persisted in existing account fields as account-bound AES-256-GCM ciphertext. The encryption key is derived from a strong server-only NEXTAUTH_SECRET; changing that secret requires fresh sign-in. Tokens never enter browser sessions, JWT claims or logs. Each live session checks guild membership afresh, and expired tokens refresh under an account lock. Confirmed departure sets GUEST, clears tokens and appends an audit record without deleting history. Rejoining requires approval again. Outages deny access without falsely recording departure. No Discord role is automatically translated into an admin role. UID is absent from public sessions, directories and audit metadata. The optional bot adapter remains an unstarted foundation; no bot token is needed for this OAuth flow. See [session policy](discord-session-policy.md) and [member management](member-approval.md).

Development offers the whitelisted identities `demo-member` (Kiri/MEMBER), `demo-officer` (Moss/OFFICER), and `demo-admin` (Yun/ADMIN). The client submits an identity ID, never a trusted role. Mock authentication requires `NODE_ENV=development` and can be disabled with `MOCK_AUTH=false`. `MOCK_AUTH=true` in production raises a configuration error. Production rejects mock session markers and development identity IDs even when a development cookie is carried over. Development uses a process-random secret if none is supplied; restarts then invalidate previous development sessions. Production never uses this fallback.

Admin layouts, pages and writes authorize independently through central domain policies. Member actions re-read actor/target roles in transactions, serialize privilege changes with a shared advisory lock and append controlled audit metadata. Mock identities cannot write live records. `/admin/members` and `/admin/members/[id]` are functional; other admin routes remain informative shells.

## Steam — LIVE Korean news and global player count

`SteamAdapter.getCurrentPlayers(appId)` returns a count, observation timestamp and MOCK/LIVE provenance. The live adapter uses the documented [ISteamUserStats GetNumberOfCurrentPlayers](https://partner.steamgames.com/doc/webapi/ISteamUserStats#GetNumberOfCurrentPlayers) on Steam's public Web API host, with a finite request timeout and validated response. App ID `2139460` identifies Once Human. The method needs no API key; any key for future supported features must remain server-only.

HOME requests `language: "koreana"`, `count: 3` and `maxLength: 200`. The server news adapter uses Steam's public [Once Human Korean RSS](https://store.steampowered.com/feeds/news/app/2139460/?l=koreana) to show publisher-supplied Korean titles and summaries. Article links point to the feed's verified Steam Store event and retain `?l=koreana`. No Steam account or API key is needed. HTML/BBCode is shortened into ordinary React text. The feed's `channel.language` still reports `en-us`, so the adapter checks actual titles and summaries for Korean text. Unavailable or invalid Korean data retains the last successful Korean cache; HOME does not automatically substitute English news.

`news-rss.ts` bounds the response to 512 KiB, rejects XML DTD/entity declarations, and validates the channel, article and GUID URLs against the requested app and official HTTPS host. The live feed had ten items when checked on 2026-10-08; this is an observation, not a fixed feed-size contract. Requests without Korean localization keep the existing [ISteamNews GetNewsForApp v2](https://partner.steamgames.com/doc/webapi/ISteamNews) path for compatibility. Valve's documented news parameters do not include a language selector, and a direct `l=koreana` API request still returned English in the check. The English path continues to validate Steam's CDN redirect because news-feed GIDs differ from announcement GIDs. Verification is recorded in `outputs/steam-korean-news-research.json`.

`server/steam-overview.ts` keeps independent process caches for news (15 minutes) and player count (5 minutes). Page requests refresh expired data; simultaneous requests share one refresh. Errors retain the last good value and observation time, with a one-minute retry delay. A cold failed request displays unavailable information rather than a fabricated count. Both LIVE and DEMO HOME use the same external-data card. HOME retains its four-second overall deadline and 3.5-second adapter timeout; public response bodies are bounded. Steam fetching runs outside member-data transactions. The count is the current global Steam player total, not a Korean-server count, historical peak or cross-platform total. Optional Steam account linking remains unimplemented.

## TH.GL — four live scenario maps and shared links

The [official embed documentation](https://www.th.gl/developers), checked 2026-10-08, publishes `/[language/]embed/maps/<Map name>` and `center`, `zoom`, `types`, `hide`, `share`. The four supported maps were opened from the [official map list](https://oncehuman.th.gl/maps), switched to Korean, and their actual Embed dialogs were checked. `ONCE_HUMAN_MAPS` records these names; English names are not guessed for Korean embed URLs.

| Scenario      | Korean embed map name        |
| ------------- | ---------------------------- |
| DEVIATION     | Deviation Secure             |
| MANIBUS       | 터치 오브 스카이&진화의 부름 |
| WINTER        | 혹독한 겨울                  |
| ENDLESS_DREAM | 무한한 꿈                    |

`/map?scenario=ENDLESS_DREAM&share=<code>` selects the map and applies a TH.GL custom filter/drawing share code. The outside controls switch scenario, apply/clear codes, copy a local shared link, open the full source map, and enter fullscreen. Changing scenario clears the previous map's code. Codes accept 1–128 ASCII letters, digits, underscores or hyphens; invalid query values show the base map with a safe notice. The new map registry requires no environment configuration. Unknown map names passed to the general URL helper still return `null`.

Each iframe retains visible TH.GL attribution and a link to that exact original map. Marker data is rendered by TH.GL and is not mirrored. Shared routes currently travel in the URL; a persisted hive route library and route editing remain future extensions. Fullscreen controls act on the outer map container only.

Farming links use `/map?scenario=<scenario>&target=<verified target key>`. The combat-deviant detail panels, selection dialog, saved build, and animal fusion materials open this link in a new tab, retaining the editor's unsaved state. Exact catalog IDs are mapped to TH.GL marker type IDs manually checked in the visible filter UI and generated Embed dialogs. Display names never enable a guessed match; furniture and unverified items have no farming link. Builds with no scenario use the first verified supported map, prefer Manibus, and name that map in the link label.

The map's farming selector groups deviants, animal materials, and mineral resources. The initial registry contains 23 combat deviants, 12 fusion animals represented by 10 filters, and 11 minerals: 44 targets supported by the filter controls of all four maps. Stag/doe share the deer distribution, and ram/ewe use TH.GL's goat/sheep group; these buttons and the map explicitly identify the common distribution rather than implying a sex-specific filter. Selecting a target applies the official `types` parameter to both iframe and original-map link. Scenario changes retain the target and clear custom share codes; farming targets take precedence over shared drawings so additional unrelated markers do not enter the filtered view. The copied local link retains its target. Unknown query keys show a safe notice; a known target whose filter is unverified on the chosen map explicitly displays the full map. The registry describes filter support, never guaranteed availability, spawn rates, or every acquisition method. TH.GL may contain no markers for a target on a particular scenario. Verification evidence is stored in `outputs/map-farming-research.json` and `outputs/map-farming-material-research.json`.

Acquisition guidance, reviewed 2026-10-08, is maintained separately in `map-farming-acquisition-data.ts` and `map-farming-deviant-acquisition-data.ts`. Every registered combat deviant has a short note and evidence links, shown both on the map and beside its build/fusion map button. The selected build/map scenario chooses any applicable override. Historical Manibus/Winter routes are labelled with their evidence scope; a different scenario without verified acquisition evidence explicitly says its detailed route is unconfirmed and omits the source-location shortcut. Provider filter support is never used as proof of scenario availability. Official updates take priority over conflicting old guides, and community reports are labelled as reports. No fixed phase number, guaranteed drop rate, or universal respawn countdown is inferred.

Wolf and other animal pins are candidate distribution points rather than live animals at every marker. Notes direct players to the game's current-scenario animal distribution tracker, added in the [September 2026 update](https://www.oncehuman.game/kr/news/devBlog/20260916/40777_1314022.html). They do not claim a uniform global random algorithm or a fixed respawn interval. Teddy's Manibus note uses the [official acquisition adjustment](https://www.oncehuman.game/kr/news/update/20250312/40776_1218377.html): THETA hidden rewards and field gathering. The other scenarios' reported alternatives are separate. The [January 2026 update](https://www.oncehuman.game/m/news/update/20260121/40780_1282991.html) replaces Mist reward routes and Workshop Defense; old versions of those farming instructions are not recommended as active content. Ended anniversary/check-in events are not presented as currently available farming routes.

Where an acquisition route is supported, the farming map also shows its verified boss or silo entrance markers alongside the deviant filter. A reviewed named site with a verified camera moves the map to that representative area and opens its reward panel. Random animal distributions and unresolved routes keep their candidate filters without a fabricated camera. The separate acquisition shortcut still shows all silo entrances when appropriate. Acquisition evidence, source dates and rejected claims are retained in `outputs/deviant-recheck-{teddy,dungeons,field,bosses}-ko.json` and `outputs/map-farming-acquisition-marker-research.json`.

### Location rewards and scenario scope

`/map?scenario=<scenario>&location=<registered key>` applies a location filter and opens its reward panel. The category selector has one **사일로** option. Its adjacent reward panel lists individual silos; clicking a name changes both the camera and curated rewards. Stable named-location links continue to work. The catalog contains 38 provider categories, 11 named silo/LEA guides and six bosses. All category IDs were checked in actual Korean Embed dialogs; evidence is in `outputs/map-location-provider-research.json`. Named silo cameras were copied after selecting each actual place on each intended map, recorded in `outputs/map-location-camera-research.json`; boss-camera evidence is in `outputs/map-boss-camera-research.json`. Provider coordinates are not inferred from in-game coordinates. Silos share the `securementsilos` marker category, so nearby entrances may remain visible around the focused place.

The iframe and original source link have the same `types`, `center` and `zoom` values. Copied local links retain the target or named place. Changing scenario retains the selection but unsupported named locations display a notice and the base map. Location selection takes precedence over targets and custom drawings, including malformed location queries, which fail closed. The [official Embed API](https://www.th.gl/developers) documents camera/filter/share parameters, without a marker-click event bridge. Provider marker popups therefore remain independent; the adjacent named list opens our curated reward panel. No undocumented messages or cross-origin DOM access are used in the product.

Rewards distinguish official routes, dated community cases, guide references and unknown pools. Manibus and Winter tables remain separate. Endless Dream has ten verified named silo entrances: five have limited reward references, and the other five explicitly show that their individual drop tables remain unknown. Teddy uses the Korean Master-hidden report for West Tower (THETA); its historical phase-three Master opening rule is separate from a permanent server's actual unlocked state and from the deviant's other routes. ALPHA, THETA, PHI, EX1 and DELTA guides do not inherit the full Manibus/Winter pool. Deviation's different capture system receives no copied classic dungeon table. City/hospital/factory categories describe crate/local loot mechanisms, not a universal item pool. Regular Mine Workshop (`mine`) and RaidZone Mining Workshop (`excavation`) remain separate. Quantities, respawn timers, exact rates and complete crate suffix pools are not inferred.

The collapsible dungeon rules cite current official changes: Controllers are no longer required, January 2026 new mod level ranges differ by difficulty, first/weekly rewards are distinct from repeats, and March 2026 blueprint-fragment rewards were replaced with Starchrom. Named reward categories are farming guidance rather than an exhaustive drop database. Detailed source dates and rejected claims are retained in `outputs/map-location-{activity,dungeon,monolith}-research.json`.

HOME shows the game's Korean official announcements through the localized Steam RSS described above, with Korean article links and observed timestamps. ## Operational constraints

Adapters enforce finite request timeouts and validate external responses. Foundation migrations are applied to local PostgreSQL 17 on loopback 5433, with 29 database verification checks passed. Local OAuth/Onboarding and administrator access have been verified with the user's real account. Membership is revalidated on subsequent live requests rather than through a running bot; idle accounts are not inspected by a background worker. Actual human-account departure/rejoin and production staging remain separate manual checks; synthetic transport and real-DB tests verify their policy and persistence. No integration credential is committed. See [Discord setup](discord-setup.md) and [operating verification](verification-live-operations.md).
