# 시즌 등록·승인·참여 관리

시즌 자체가 게임 서버를 뜻합니다. 시나리오와 숫자 네 자리로 주소를 결정하고, 서버 유형·트랜스 현상·시즌에서 사용할 하이브 이름·지역·시작일을 입력합니다. 서버를 별도로 등록하는 화면은 없습니다. 내부 서버 참조는 기존 데이터와의 호환을 위해 유지합니다.

## 등록과 수정

`/admin/seasons`와 `/admin/seasons/new`는 같은 `SeasonSetupForm`을 사용합니다. 일반 멤버는 `/season/new`에서 같은 폼으로 등록을 신청합니다.

- 시즌 번호와 서버 주소 입력은 하나입니다. `E_Dream-X0070`의 `0070`이 시즌 번호이며 영문 접두어는 시나리오 선택으로 결정합니다. 앞자리 0을 유지합니다.
- 서버 유형은 ‘일반(시즌제)’ 또는 ‘영구’를 선택합니다. 트랜스 현상은 이 유형이나 시나리오와 별도로 선택하며 무한의 꿈에서도 같은 선택을 사용합니다.
- 트랜스 현상은 ‘없음’, ‘달의 징조’, ‘역행하는 별’, ‘달빛의 향연’, ‘뒤틀린 공존’, ‘중력의 심연’을 기록할 수 있습니다. 테마가 바뀌면 기존 시즌을 수정하며 참가 명단·단계 진행·투표 이력은 유지합니다.
- 하이브 이름의 표시는 ‘시즌에서 사용할 하이브 이름’입니다. 생성 후에도 수정할 수 있습니다.
- 일반(시즌제)의 정산일은 기본적으로 표시하지 않으며 ‘정산일 추가 (선택)’를 켜서 입력합니다. 처음에 비워두고 나중에 추가하거나 지울 수 있습니다. 영구 서버에는 정산일을 설정하지 않습니다.
- 시작·정산·투표 날짜는 달력과 한국 시간(KST) 입력을 사용합니다. 변경하지 않은 기존 시각의 초·밀리초는 유지합니다. 단계 이름과 날짜를 입력하는 폼은 제공하지 않습니다.
- 승인된 운영진은 상세 화면에서 시나리오·번호·지역·하이브 이름·일정을 수정합니다. 보관된 시즌도 같은 상태를 유지하면서 정보를 수정할 수 있습니다. 기존 단계·작전·투표를 일정 밖으로 밀어내는 수정은 거부합니다.
- 일반 멤버는 본인 승인 대기 신청을 수정할 수 있고, 반려된 신청을 수정하면 다시 승인 대기로 제출됩니다.

| 시나리오                 | 주소 형식         |
| ------------------------ | ----------------- |
| 비정상수용(Deviation)    | `Deviation-X0000` |
| 땃쥐(Manibus)            | `Manibus-X0000`   |
| 설산(The Way Of Winter)  | `W_Winter-X0000`  |
| 무한의 꿈(Endless Dream) | `E_Dream-X0000`   |

같은 시나리오·시즌 번호·서버 유형은 중복 등록하지 않습니다. 같은 시나리오와 번호라도 일반(시즌제)과 영구 서버는 각각 등록할 수 있습니다. 다른 시나리오에서도 같은 숫자를 사용할 수 있습니다. `0000`도 네 자리 주소로 허용합니다. 트랜스 현상 변경은 새 주소를 만드는 동작이 아닙니다.

기존 기록에서 확인할 수 없는 서버 유형과 트랜스 현상은 ‘미확인(기존 기록)’으로 보존합니다. 중력 콘텐츠의 기존 설정만으로 서버 유형이나 정확한 트랜스 테마를 추정하지 않습니다. 해당 기록을 확인한 뒤 수정 화면에서 분류합니다. 트랜스가 미확인인 동안에는 기존 중력 콘텐츠 설정을 유지하고, 명시적인 테마를 선택하면 그 테마에 따라 중력 콘텐츠 사용 여부를 판단합니다.

## 트랜스 현상의 운영 근거

트랜스 현상(영문 Visional Wheel)은 시나리오에 적용되는 추가 테마입니다. [S4 공식 영문 개발자 글(2026-05-23)](https://www.oncehuman.game/news/devBlog/20260522/40781_1301328.html)은 중력의 심연의 적용 시나리오에 무한의 꿈을 포함하고, 기존 트랜스 태그 서버의 테마가 자동 전환된다고 설명합니다. [월드 개편 공식 안내(2026-05-25)](https://www.oncehuman.game/news/devBlog/20260525/40781_1301445.html)는 프리즘버스를 제외한 같은 서버에서 일반 월드와 트랜스 월드를 전환할 수 있다고 명시합니다.

이 서비스의 선택 항목은 하이브가 참여 중이거나 참여했던 서버 환경을 기록합니다. 과거 테마를 선택할 수 있어도 게임에서 모든 과거 트랜스 테마를 동시에 이용할 수 있다는 뜻은 아닙니다. 테마의 자동 갱신이나 게임 서버 이동을 실행하지 않으므로 게임의 현재 환경을 확인한 운영진이 기록을 갱신합니다.

반년 고정 주기를 적용하지 않습니다. 초기 [2025-01-15 공식 안내](https://www.oncehuman.game/news/update/20250115/40780_1207023.html)는 약 3개월을 안내했으나 실제 후속 시작일은 [S1 2025-05-21](https://www.oncehuman.game/news/update/20250521/40780_1235735.html), [S2 2025-09-24](https://www.oncehuman.game/m/news/update/20250916/40780_1259618.html), [S3 2026-01-21](https://www.oncehuman.game/news/devBlog/20260119/40781_1282577.html), S4 2026-05-27(모두 PT)로 약 4개월 간격이었습니다. [2026-09-16 공식 Steam 공지](https://steamcommunity.com/games/2139460/announcements/detail/689768958096572532)는 S4 종료를 2026-11-18 PT(한국 공지 기준 11월 19일)로 연기했습니다. 이번 S4는 약 반년이지만 다음 테마의 주기를 고정값으로 가정하지 않습니다.

해외 커뮤니티에서도 [무한의 꿈과 달빛의 향연을 함께 플레이한 토론(2025-09-30)](https://www.reddit.com/r/OnceHumanOfficial/comments/1ntymyq/endless_dream_with_lunar_revelry_is/)과 [트랜스와 시나리오 단계의 구분을 설명한 토론](https://www.reddit.com/r/OnceHumanOfficial/comments/1qdaq5i/visional_wheel_s3_3_types_of_polluted_zones_will/)을 확인했습니다. 커뮤니티의 난이도 평가는 개인 경험이며 적용 시나리오와 운영 일정은 공식 공지를 기준으로 합니다.

## 승인과 공개

관리자(ADMIN)·운영진(OFFICER)이 만들면 준비 중(PLANNED) 시즌으로 즉시 등록됩니다. 일반 멤버(MEMBER)의 생성은 승인 대기(PENDING) 상태입니다. 관리자만 승인·반려할 수 있으며, 승인하면 일반 시즌 목록에 표시되고 직접 참여가 열립니다. 승인 상태는 진행 상태와 별개입니다.

승인 대기·반려 신청은 운영진과 신청자 본인만 볼 수 있습니다. HOME·작전·일반 시즌 목록에는 승인된 시즌만 사용합니다. 승인되지 않은 시즌은 참가 등록·단계·작전·투표 등 운영 대상으로 사용할 수 없습니다. APPLICANT·GUEST·Mock 계정은 실제 신청과 참여가 불가능합니다.

## 참가자 관리

승인된 Discord 멤버는 `/season`의 준비 중·진행 중 시즌에서 ‘참여하기’를 눌러 직접 참가합니다. 중복 참여는 기존 기록을 유지합니다. 정산·보관 상태에서는 직접 참여를 받지 않습니다.

관리자는 상세 화면에서 참가자를 추가하고, 이동 준비 상태를 수정하거나 참가 명단에서 삭제할 수 있습니다. 삭제는 `removedAt`과 `removedById`로 표시하며 활성 명단·인원·권한에서 제외합니다. 기존 투표의 외래 키, 최초 참여일과 감사 기록은 유지합니다. 관리자가 다시 등록하거나 멤버가 열린 시즌에 다시 참여하면 같은 참가 기록을 복구하고 이동 상태를 미정으로 초기화합니다.

참가자 수정·삭제와 시즌 검토는 ADMIN만 처리합니다. 기존 운영진의 참가자 추가 권한은 유지합니다. 보관 상태에서도 관리자의 참가자 관리는 가능합니다.

## 시나리오 단계와 상세

헤더 SEASON은 `/season` 목록이며, 선택한 시즌의 `/season/[id]` 상세에서 진행 단계와 참가 정보를 확인합니다. 전체 진행 중인 시즌을 고르는 HOME 허브와 달리 이 상세의 단계·참가 인원·이동 상태는 URL로 선택한 시즌에만 해당합니다.

| 시나리오   | 자동 구성 순서                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------- |
| 비정상수용 | 1단계 → 2단계 → 3단계                                                                              |
| 땃쥐 일반  | 공중의 그림자 → 스타로이드 제어 → 스타더스트의 포효 → 터치 오브 스카이 → 새로운 새벽               |
| 설산 개편  | 얼어붙은 땅 → 하늘을 메우는 불씨 → 꺼지지 않는 불씨 → 동틀 무렵                                    |
| 무한의 꿈  | 악몽의 부상 → 이상한 꿈의 확산 → 불길한 징조의 침식 → 현실과 허상의 교차 → 끝없는 어둠 → 무한한 꿈 |

비정상수용은 사용자 요청에 따라 이름을 일반적인 세 단계로 구성합니다. 땃쥐는 [공식 개편표](https://www.oncehuman.game/kr/news/update/20250321/40776_1221187.html), 무한의 꿈은 [공식 정식 출시 공지](https://www.oncehuman.game/kr/news/update/20250702/40776_1244585.html)를 기준으로 합니다. 설산은 [공식 개편 기간](https://www.oncehuman.game/kr/news/update/20250716/40776_1247683.html)과 [2026년 한국 플레이 기록](https://gall.dcinside.com/mgallery/board/view/?id=oncehumankor&no=280818)을 대조한 네 단계입니다. 초보자 땃쥐·구버전 설산의 구성은 사용하지 않습니다.

일반(시즌제)은 생성 시 단계와 현재 번호 1을 함께 저장합니다. 날짜가 지나도 자동으로 바뀌지 않습니다. 승인된 비보관 일반 시즌에서 ADMIN만 이전·다음 버튼을 사용하며 처음과 마지막의 범위를 벗어나지 못합니다. `CHANGE_SEASON_PHASE`는 시즌 ID·버전·방향만 받아 현재 역할을 확인하고, 같은 버전의 중복 제출을 거부하며 이전·다음 번호와 처리자를 감사 기록에 남깁니다. OFFICER에게는 진행 버튼 권한이 없습니다.

영구 서버는 항상 ‘휴식기’로 표시하고 단계 목록과 이전·다음 진행을 제공하지 않습니다. 서버에서도 영구 서버의 단계 변경을 거부합니다. 일반 시즌을 영구로 분류하더라도 기존 단계 행과 날짜는 삭제하지 않고 이력으로 보존합니다.

일반(시즌제)은 마지막 단계에만 HIVE 시즌 이동 신청·준비 상태가 표시됩니다. 참가자는 참가 예정·사전 등록·준비 완료·이동 완료를 저장합니다. 승인된 준비 중 시즌도 관리자가 마지막 단계로 설정하면 참가자가 신청할 수 있으며 보관 상태는 읽기 전용입니다. 이전 단계로 되돌리면 신청 폼이 숨겨지고 기존 참가·투표·이동 기록은 유지됩니다. 게임 서버 이동을 실행하지는 않습니다.

영구 서버의 HIVE 이동 신청은 단계와 별도로 관리합니다. 새 영구 서버는 이동 신청이 닫힌 상태로 생성되며, 승인된 영구 서버의 상세 수정 화면에서 ADMIN만 신청을 열거나 닫을 수 있습니다. 신청을 열어도 ‘휴식기’ 표시와 참가 명단은 유지합니다. 닫으면 새 이동 상태 입력을 차단하고 이미 저장한 이동 준비 상태는 보존합니다. 일반 시즌의 이동 신청은 기존 마지막 단계 규칙을 따릅니다.

시나리오를 바꾸면 새 시나리오의 단계로 교체하고 1단계로 초기화합니다. 기존 단계 ID·일정과 초과 단계 행은 역사 자료로 보존하고 새 템플릿의 단계 수를 넘는 행은 현재 화면·진행·마지막 단계 판단에서 제외합니다. 이 교체 전후 명칭과 진행 번호를 감사 기록에 보존합니다. 전체 시즌의 계획·진행·정산·보관 상태는 이전·다음 버튼으로 바뀌지 않습니다.

## 저장·권한·기록

`CREATE_SEASON_SETUP`과 `SAVE_SEASON_SETUP`은 시나리오 키·네 자리 번호·서버 유형(`serverType`)·트랜스 현상(`trancePhenomenon`)·지역·하이브 이름·시작일·선택 정산일을 받습니다. 영구 서버의 이동 신청 개폐는 `SAVE_SEASON_SETUP`의 `migrationOpen`으로 저장합니다. 서버에서 숫자로 시즌 번호를 결정하고, 신규 서버 참조·시즌·감사 기록을 함께 저장합니다. 수정은 `id`와 `expectedUpdatedAt`을 받아 오래된 화면의 덮어쓰기를 거부합니다. 상태·투표 필드는 승인된 시즌을 관리하는 운영진만 변경합니다. 서버 유형·트랜스 현상·이동 신청 개폐 변경은 `season.environment.changed`에 변경 전후 값과 처리자를 기록합니다.

`REVIEW_SEASON`, `UPDATE_MEMBERSHIP`, `REMOVE_MEMBER`는 저장 시 현재 관리자 역할을 다시 확인합니다. 참가 정보 수정도 해당 참가 기록의 버전을 확인합니다. `ENROL_MEMBERS`는 현재 승인 상태와 Discord 연결을 확인합니다. `ADD_PRESET_CANDIDATE`는 네 가지 시나리오 중 후보를 선택하고 필요한 내부 시나리오 참조를 함께 등록합니다.

기존 내부 `SAVE_SEASON`, `CREATE_SCENARIO`, `CREATE_SERVER`, `REGISTER_SERVER` 계약은 호환을 위해 남겨두며 서버 등록 양식은 제공하지 않습니다. 새로운 시즌 수정은 기존의 참가 이력에 따른 주소 수정 제한 대신 요청된 편집 기능을 사용합니다. 일반(시즌제) 서버의 진행 상태는 계획 → 진행 → 정산 → 보관 순서를 유지하고, 보관 상태를 되돌리지는 않습니다. 일반 서버 활성화에는 현재 단계가 필요하며, 정산일이 없는 시즌도 활성화할 수 있습니다. 영구 서버는 단계 조건 없이 계획 → 진행 → 보관으로 운영하며, 운영 시작 이전 활성화 및 예정 작전이 남아 있는 상태의 보관은 허용하지 않습니다.

읽기와 쓰기 모두 실제 세션과 최신 DB 역할·Discord 연결을 확인합니다. 공통 advisory lock `912743110`을 먼저 얻고 작성자·시즌·참가 기록 순서로 잠급니다. 승인·권한 갱신·작전·투표와 같은 순서를 사용합니다. DTO에는 등록 정보와 공개 멤버 이름만 포함하며 게임 UID·이메일·OAuth 토큰은 포함하지 않습니다.

## DB 변경과 검증

`0001_season_participation.sql`은 선택 정산일, 승인 상태·작성자·검토자와 참가 삭제 정보를 추가합니다. 전체 번호 중복 제한을 시나리오별 번호 제한으로 바꿉니다. 기존 시즌은 승인 상태로 유지하며 사용자·서버·기록을 삭제하지 않습니다.

`0002_manual_season_phases.sql`은 현재 단계 번호를 추가하고 기존 네 시나리오 시즌에 고정 단계를 보충합니다. 바뀐 기존 명칭을 감사 기록에 보존하며 단계 ID·날짜·참가 기록을 삭제하지 않습니다.

`0005_season_environments.sql`은 서버 유형·트랜스 현상·이동 신청 개폐를 추가합니다. 기존 서버 유형과 테마는 `UNKNOWN`, 이동 신청은 `false`로 보존하며 기존 중력 콘텐츠 플래그를 덮어쓰지 않습니다. 주소 중복 제한은 시나리오·번호·서버 유형별로 적용합니다. 영구 서버의 정산일과 일반 서버의 별도 이동 신청 개방은 데이터베이스에서도 허용하지 않습니다.

정책 테스트와 실제 PostgreSQL 검사는 신청 → 반려 → 수정 → 관리자 승인, 관리자 즉시 생성, 본인 신청 접근 제한, 직접 참여와 중복 방지, 참가자 수정·삭제·복구, 보관 상태 편집, 선택 정산일과 기록 보존을 확인합니다. 테스트 fixture는 되돌리거나 자체 생성한 식별자만 정리합니다.

`apps/web/tests/season-environment.integration.ts`는 일반·영구 서버의 같은 번호 등록, 목록·상세의 독립적인 환경 표시, 트랜스 변경 시 단계·참가·투표·감사 기록 보존, 영구 서버 이동 신청 개폐와 권한, 영구 단계 변경·정산일 거부, 미확인 기존 기록의 보존을 확인합니다. 중력 테마에서 다른 테마로 바뀌면 기존 응축기 파티의 새 참가·미정 응답을 차단하고 기존 참가자의 불참 변경을 허용하는지도 HOME·파티 상세·저장 경로에서 확인합니다. 실제 PostgreSQL 검사는 로컬 `uniz_hive`만 허용하고 전체 fixture를 바깥 트랜잭션으로 되돌립니다. 실행 명령은 `pnpm exec vitest run --config vitest.integration.config.ts apps/web/tests/season-environment.integration.ts`이며 전체 통합 검사는 `pnpm ops:verify`입니다.
