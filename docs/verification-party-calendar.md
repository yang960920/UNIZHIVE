Chrome의 실제 승인 계정으로 모집 생성, 예정 시즌 참가, 운영진의 참가 응답 변경·제외, 콘텐츠·정원·장소 수정, 모집 취소와 취소 후 신청 차단을 확인했습니다. 저장 후 참가 관리 선택값이 이전 값으로 돌아가는 문제를 수정하고 저장된 응답과 선택값의 일치를 재확인했습니다. 홈의 다음 파티 및 달력 연결도 확인했습니다.

모바일 폭 390px에서 달력과 편집 폼의 가로 넘침이 없고 날짜 목록이 펼쳐짐을 확인했습니다. 브라우저의 한국어 시간 입력이 잘리지 않도록 시간 칸을 넓혔으며 작은 화면에서는 날짜·시간을 세로로 배치합니다. 검수용으로 생성한 파티는 취소 동작 확인 후 정확한 ID·제목·안내·상태를 검사하여 관련 임시 기록만 제거했습니다. 기존 시즌·멤버·빌드는 보존했습니다.

SQL 검사는 시즌별 조회 격리, KST 경계, 9개 모집의 4개·4개·1개 페이지 조회와 달력 전체 모집 수 유지, 참가 명단 후속 등록, 시즌 제외에 따른 미래 예약 해제와 과거 기록 보존, 비활성 콘텐츠의 긍정 응답 거절 및 예약 취소 허용, 이전 관리 경로의 신규 파티 수정 차단을 포함합니다. 서버 쓰기 검증에서는 정원·권한·오래된 화면 충돌도 확인했습니다.

처음 여러 검사를 동시에 실행할 때 Windows에서 테스트 프로세스 종료와 DB 검사 시간 초과가 발생했습니다. 기능 검사 작업자를 2개로 제한하고 DB 검사를 직렬로 실행해 모두 통과했습니다. 기본 `pnpm test`에도 같은 작업자 제한을 적용했습니다. 제품의 서버 처리 방식을 변경한 설정은 아닙니다.

화면 기록은 `artifacts/party-calendar/`, 별도 빌드의 설정 보존·임시 파일 정리 결과는 `outputs/party-build-check/build-result.json`에 저장했습니다. 검수 중 파티가 표시된 캡처는 임시 기록의 화면이며 최종 캡처에는 해당 기록이 없습니다.
